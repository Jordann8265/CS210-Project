For my final project, I developed an item-tracking application for the Corner Grocer to help them analyze daily purchase records and figure out how to rearrange their produce section to better serve customers. The program processes a chronological text file of purchases (CS210_Project_Three_Input_File.txt), tallies item frequencies using a map, and automatically generates a frequency.dat backup file right at startup without user intervention. Through an interactive menu, users can look up individual item counts, view a full numerical list, or check out a visual histogram of all purchases.   

I feel I did a particularly strong job keeping the codebase clean and organized by separating everything into dedicated header and implementation files, alongside a GrocerTracker class that properly implements public and private sections. To ensure the program remains maintainable, readable, and adaptable, I used descriptive naming conventions, added clear in-line comments to explain block logic, and cleanly separated the user interface logic in main.cpp from the underlying data processing.   

The most challenging parts to write involved managing multi-file compilation and ensuring the map data correctly populated the backup file. I overcame these hurdles by breaking the project down incrementally—testing the constructor and file input/output streams first before building the menu loops—and relying on compiler feedback and course readings for support. Moving forward, I could enhance the code by implementing case-insensitive string searches and more robust error handling for file paths, which would make the program more efficient and secure.
Ultimately, the experience of handling file streams, implementing object-oriented principles like encapsulation, and working with standard containers will be immensely transferable to my future coursework and software development projects.
